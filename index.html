How it works

From files to trusted outputs
in four steps.

01

Structure your workspace

Create a workspace with 8 standard folders — agents, skills, memory, sources, artifacts, and more. Everything lives as real, editable files.

No hidden prompt databases. Every instruction, skill, and memory entry is visible in the file tree.

02

Connect any agent

Issue a scoped HMAC key. Your agent discovers skills as callable prompts, reads sources, and writes outputs — all within the limits you set.

Any agent that supports MCP or the Agent Access API connects in minutes. No vendor lock-in.

03

Review before it lands

Writes to sensitive paths stage as line-by-line diffs. You see exactly what the agent wants to change before it happens.

Accept, reject, or edit. Nothing touches your files without your sign-off.

04

Iterate with confidence

Every run builds on the last. Skills improve, memory accumulates, and the audit trail tells you exactly what changed and why.

Key rotation, scope changes, and revocation happen instantly — no redeployment needed.

Every instruction set, persona, and workflow rule is a versioned file in the workspace. Your agents read them directly. When you update a file, every agent using it updates too — no copy-paste, no drift.

Agent definition

Define once.
Run with confidence.

Every agent in Filepad operates from a declarative definition. What it can read, what it can write, what requires your approval. Declared explicitly — not inferred from a prompt.

agent.yamlvalid
# agent definition · filepad workspace
agent:
id: research-assistant
workspace: acme-corp
instructions: instructions.yaml
memory:
store: memory.store
scope: workspace
skills:
- skills/search.ts
- skills/write.ts
- skills/email.ts
review:
required_for: [write, send, delete]
approver: workspace_owner
